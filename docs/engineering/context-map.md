# 上下文地图与事实归属

架构规则由 [架构文档](architecture.md) 维护。本文只维护本项目限界上下文、状态所有权和协作契约。D2 已实现三个上下文的核心能力和公开协作，D3 已扩展灰度、版本浏览/差异/回滚；环境流转在 D4 实现。

## 上下文

| 上下文   | 拥有的事实                                     | 核心模型                                         | 对外应用契约                          |
| -------- | ---------------------------------------------- | ------------------------------------------------ | ------------------------------------- |
| Flags    | 环境配置、规则顺序、灰度、版本、评估和发布结果 | Flag 聚合、Rule、ConfigVersion、EvaluationResult | 配置查询/修改、评估、复制、发布、回滚 |
| Identity | 用户身份、角色、会话有效性与操作权限           | User、Session、Role、AccessPolicy                | 登录/退出、会话解析、授权查询         |
| Audit    | 真实操作者、配置变更记录与历史查询             | AuditEntry                                       | 事务内追加记录、历史查询              |

React、HTTP、PostgreSQL、迁移和 Docker 不属于业务上下文。跨上下文应用外壳属于 presentation，依赖装配属于 platform。

## 统一语言

- Flag：由环境与 Key 定位的一份布尔功能配置。
- Rule：具有唯一优先级的属性或百分比匹配规则。
- ConfigVersion：一次成功变更产生的不可修改完整快照。
- Revision：当前配置的单调递增版本号，也是并发写入的比较依据。
- Evaluation：针对一个版本和用户属性产生的结果与判断轨迹。
- Copy：在目标环境创建新聚合；目标已存在则冲突。
- Publish：将选定源版本应用到已有目标聚合。
- Rollback：用历史内容形成一个新版本，而非删除后续历史。
- AuditEntry：成功配置变更的操作证据，不是配置版本，也不能据此直接恢复配置。

## 协作契约

| 发起方          | 调用方端口        | 提供方                | 不变量                                               |
| --------------- | ----------------- | --------------------- | ---------------------------------------------------- |
| Flags 写入用例  | AuthorizationPort | Identity 授权用例     | 每个入口都校验目标环境的操作权限；操作者来自有效会话 |
| Flags 提交用例  | AuditAppendPort   | Audit 追加用例        | 审计失败则配置与版本全部回滚                         |
| HTTP 会话中间件 | SessionResolver   | Identity 会话解析用例 | 无效会话不产生可信 Actor                             |
| Audit 查询用例  | AuthorizationPort | Identity 授权用例     | 历史查询遵守只读访问权限                             |

端口名为计划名称，落地时保持同一职责，可按 Go/TypeScript 命名习惯调整。提供方只暴露稳定 DTO 与应用入口；调用方不能导入提供方内部仓储或领域实体。

Flags 和 Audit 的写入适配器共享同一数据库事务，但业务归属不合并。platform 负责把事务绑定的公开用例装配给调用方端口，不由 domain 管理连接池或 SQL transaction。

## 单一事实来源

- 评估规则：Flags 的 EvaluationPolicy；前端只呈现后端结果。
- 已提交配置：PostgreSQL 中当前 revision 指向的 ConfigVersion。
- 规则编辑状态：Flags 聚合；前端表单是尚未提交的副本。
- 权限：Identity 的 AccessPolicy；按钮显示只消费能力结果。
- 版本与回滚：Flags 的版本用例；Audit 不承担版本恢复。
- 操作者：Identity 解析的 Actor，禁止从请求 JSON 自报身份或角色。
- UI 临时状态：presentation；任何拖拽预览和缓存都不成为服务端事实。

## 必须保持的结果

1. 相同配置快照和相同属性始终得到相同评估结果。
2. 一次配置修改的当前数据、完整版本和审计记录同时存在或同时不存在。
3. 过期 revision、无权限请求和业务冲突不产生部分写入。
4. 所有 production 修改入口使用同一管理员权限策略。

新增跨上下文能力时，同时更新本文、相关业务文档、端口契约与最低有效测试；不能仅添加一个绕过边界的 import。
