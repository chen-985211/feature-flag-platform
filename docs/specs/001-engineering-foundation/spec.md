# Spec：工程基础与可验证运行入口

状态：已完成 D1，验收见 [验证记录](verification.md)。来源：用户已确认完整方案、DDD/Clean、SDD/TDD 和金字塔，并于 2026-10-08 授权“先开始任务”。本规格沿用这些决定，不额外申请重复审批。

## 目标与范围

让 React、Go 与 PostgreSQL 的项目具备可复现、可验证的开发入口，为后续身份、Flag 和原子版本提交提供正确边界。最终交付支持 Docker；真实线上部署不在本次要求内。

本任务完成工具链与分层装配、配置校验、数据库健康检查、基本 React/API 接线、隔离测试命令及迁移基础。Flag CRUD、登录、完整评估、发布/回滚在后续业务任务中验收，不能把基础页面当业务功能完成。

## DDD 与状态归属

业务上下文沿用 Flags、Identity、Audit，本阶段不创造“配置”或“健康检查”的虚构业务聚合。

- platform 拥有进程配置、连接池、HTTP 生命周期和技术就绪状态。
- domain/application 不依赖启动配置、HTTP 或具体数据库库。
- 数据库保留已提交状态；界面状态不是数据库事实。
- API 错误契约在 HTTP 边界表达，内部连接错误不传给用户。

主要不变量：非法配置不会启动一个错误服务；存活不等于数据库就绪；健康错误不泄露数据库凭据；普通 unit 不依赖真实数据库。

## 外部行为

1. 缺少或非法数据库地址、监听地址、应用 Origin 或会话期限时明确指出配置项，消息不携带秘密原值。
2. 存活端点在进程正常服务时返回成功，即使数据库暂不可用。
3. 就绪端点真实检查 PostgreSQL，在超时、取消或失败时返回不可用，不暴露数据库错误正文。
4. 关闭信号触发有界优雅关闭，释放本次服务与连接池。
5. 前端通过应用用例与 HTTP adapter 请求 Go API，展示真实就绪结果。
6. 启动、检查、测试和构建命令按实际完成情况标记；不以空命令或测试 skip 伪装通过。

## 2026-10-08 D1 收尾补充

用户授权完成 D1，并要求先提交现有内容，再把工程检查统一迁移到 Node。已有基础提交为 `8466d9b`。本次继续执行 S4～S6，不增加线上部署或业务功能。

- EF-09：文档、规模、依赖与任务编排使用 Node，不要求 Python；Go 分析仍由原生 Go 工具执行。
- EF-10：前端类型、ESLint、Prettier、dependency-cruiser、Knip，以及后端 gofmt、go vet、golangci-lint 与包边界检查都有失败退出码。通过临时违规验证门禁有效。
- EF-11：本地完整验证和 CI 共用入口；前端构建资源内嵌到 Go 服务，可验证页面、静态资源与 API 同源访问。
- EF-07 细化：迁移建立 users/sessions、flags/rules、flag_versions/audit_entries。环境 Key、优先级、规则形状、角色与版本外键由数据库约束兜底；当前版本外键延迟到提交检查，允许同事务插入当前配置和快照。迁移不创建演示业务数据。
- EF-06 细化：应用用例拥有就绪查询端口，HTTP adapter 解析未知 JSON；React 通过注入用例显示加载、就绪、不可用和连接失败，并提供刷新和主题切换。

测试数据库使用显式 TEST_DATABASE_URL、要求库名以 `_test` 结尾且不同于开发库。每个测试使用独立 schema，提交真实事务后断言，只清理自己创建的 schema。

## 风险与可行性

本机观察：Go 1.27.0、Node 25.2.1、pnpm 10.33.0、PostgreSQL 17.7，数据库本地 socket 已就绪；Docker 命令不可用。官方 Node 发布列表有 24.21.0 LTS；宿主 Node 25 不作为项目支持基线。

优先验证本地 PostgreSQL；Docker 文件需要后续真实容器运行才能完成 F13。网络与依赖获取可能耗时，不能把下载失败当作行为 Red。
