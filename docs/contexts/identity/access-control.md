# 登录、会话与权限

Identity 拥有身份与授权策略，后端为权威。D2 已实现登录/退出、持久化会话及 admin/editor/viewer 三种角色；自助注册、SSO 与完整用户管理后台不在已确定范围内。

## 权限矩阵

| 操作                                             | admin | editor | viewer |
| ------------------------------------------------ | ----- | ------ | ------ |
| 查看配置、版本和操作历史                         | 允许  | 允许   | 允许   |
| 在线评估                                         | 允许  | 允许   | 允许   |
| development/staging 创建、编辑、启停、规则、排序 | 允许  | 允许   | 拒绝   |
| 复制到 development/staging                       | 允许  | 允许   | 拒绝   |
| 发布到 development/staging                       | 允许  | 允许   | 拒绝   |
| development/staging 回滚                         | 允许  | 允许   | 拒绝   |
| production 任意配置写入                          | 允许  | 拒绝   | 拒绝   |

权限根据实际目标环境判定，不根据来源环境、UI 路由或按钮状态判定。production 写入包括新建、编辑、Key 改名、启停、规则增删改、灰度、排序、复制、发布和回滚。

所有业务 API 需要有效会话；健康检查与登录入口例外。前端可消费能力 DTO 呈现入口，直接请求 API 仍必须由后端独立校验。

## 会话与凭据

- 密码使用 bcrypt 哈希保存；登录错误不泄露账户是否存在，设置合理请求限制与失败反馈。
- 会话令牌由安全随机源生成，数据库只保存令牌摘要、用户 ID、到期及撤销状态。
- Cookie 使用 HttpOnly、SameSite=Lax、明确 Path/有效期；HTTPS 发布启用 Secure，本地 HTTP 配置明确区分。
- 状态修改端点使用明确的 Origin 校验和会话绑定 CSRF token；退出使用非 GET 请求并撤销服务端会话。
- 会话到期、注销或不存在返回未登录；有身份但权限不足返回无权限。
- 角色以服务端用户记录为准，不能信任客户端 role 或可修改的缓存。
- 用户标识与 Actor 由会话解析产生，业务请求不得自报操作者身份。

密码哈希、随机生成和会话存储通过应用层端口；Cookie 与请求协议属于 HTTP 适配器，domain 不感知 HTTP。

## 演示数据

提供三种角色的演示用户和有效演示配置。seed 命令显式执行，重复执行不覆盖已修改配置或重置真实账户密码。可演示凭据由初始化配置确定，部署后真实验证其角色能力。

线上演示与开发数据库隔离；敏感凭据不写入 AI 记录、diagnostic log、截图或版本快照。

## 验证

权限矩阵使用表驱动 unit 测试。登录、退出、过期/撤销、Cookie 属性、Origin/CSRF、缺少会话、伪造角色与 production 拒绝通过真实 HTTP 集成/契约测试验证。

至少直接请求每类写入 API，证明 editor/viewer 不能绕过前端进入 production。浏览器 E2E 只证明登录后导航、受限入口和退出等完整会话接线，不逐项重复权限矩阵。
