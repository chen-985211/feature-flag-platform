# D4 排序与环境流转 Spec

状态：已完成并本地验收。基线 f6ade54；用户「继续」授权执行已确定 D4。复用配置、评估、权限与审计语义，无新增核心决策。证据见 [验证记录](verification.md)。

## 范围与事实归属

Flags 拥有完整规则顺序、固定源版本、目标配置及发布结果；Identity 决定实际目标环境写权限；Audit 同事务记录目标变更及来源。前端临时拖拽/选择/确认状态不成为已提交事实。D5 演示/稳定性、D6 Docker 不在本阶段。

## 验收

- D4-01：排序必须提交恰好覆盖当前规则的完整 ID 序列和 expected_revision；拒绝重复、缺少、额外及其他 Flag ID，合法提交按序形成 priority 1～N，保留规则内容/ID/seed。
- D4-02：拖拽即时显示待提交顺序，释放后提交；键盘与上移/下移进入同一排序动作。失败恢复权威顺序并显示错误，冲突不自动重试，提供刷新入口；只读账号不能排序。
- D4-03：复制明确选定源 revision 到不同环境，新目标 ID/规则 ID、revision 1，内容/顺序/seed 与该源版本一致。已有同 Key 返回冲突，不覆盖；源后续修改不影响已选版本。
- D4-04：发布预览以固定源 revision 查找目标环境同 Key 的现有 Flag，返回目标 ID/revision、完整源/目标配置和稳定内容差异。目标缺失明确提示先复制；同环境/同 Flag 拒绝。
- D4-05：发布保留目标 ID/Key/环境/创建时间，应用源名称/启停/默认值/seed/完整规则顺序，规则使用目标自身新 ID；目标 revision 加一，来源及双方旧历史保留。发布差异忽略跨环境规则 ID 的技术差异。
- D4-06：排序、复制、发布复用统一事务提交配置/完整版本/审计；实际审计失败、Key 冲突、非法序列、旧目标 revision 或并发竞争不留下部分修改。审计复制/发布包含源 Flag/环境/revision 和实际 Actor。
- D4-07：以实际目标环境授权全部新写入口；viewer 禁止任何写入，editor 禁止 production 排序/复制/发布，admin 可操作；会话/Origin/CSRF 边界仍有效。
- D4-08：环境流转弹窗明确源版本、目标环境、完整内容/差异与确认；失败保留选择，旧预览冲突后阻止盲目重试。支持焦点、Escape、关闭后焦点返回、主题和窄屏。
- D4-09：新增第三条真实 Playwright 创建/规则→复制 staging→修改 source→选定版本发布 staging→评估目标与来源审计链路；排序分支和权限矩阵下沉到 unit/component/真实数据库/HTTP。

## 边界

源 revision 只引用不可变版本，服务端读取内容，不接受客户端提交快照。发布请求明确 target_id 与 expected_revision，再次检查目标 Key、环境及当前 revision；目标被改名或修改，旧预览不得覆盖。允许选定历史源 Key，按该版本 Key 定位目标。

每次复制/发布为目标规则生成新 ID，不引用源规则实体；差异只比较配置语义和规则顺序，保留原始 ExpectedJSON 文本，不因跨环境 ID 或技术时间制造变化。规则上限、24 KiB、安全整数和分页限制沿用现有实现。

当前基础 schema 与删除/插入规则策略已能支持原子排序，无新增依赖或迁移。完成条件为最低有效 TDD、真实事务与权限验证、完整门禁、真实浏览器截图和如实记录。
