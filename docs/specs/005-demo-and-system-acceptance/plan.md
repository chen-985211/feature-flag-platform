# D5 Plan：演示初始化与系统验收

状态：已验证。对应 [Spec](spec.md)，授权复用既定范围和用户「继续」。

## 架构与数据

Flags application 增加完整演示初始化用例和稳定数据，仍经 domain.Restore 校验；事务 Scope 新增创建存在则保留的端口。SQL adapter 用主键 ON CONFLICT DO NOTHING 处理并发，只有实际创建者写完整规则/版本；现有普通 mutation 保持既有行为。初始化在单一 Within 中遍历完整数据并逐个追加真实创建审计。

cmd/seed 作为 CLI 装配入口保留账号模式，demo 参数启用完整示例；platform/bootstrap 读取 Identity 中真实 admin Actor，共享 Flags 服务装配，避免第二套审计接线。Node 增加 seed:demo 和 E2E 稳定性入口。无新依赖/schema/API。

## 金字塔与门禁

应用 unit 证明授权及保留策略；真实 PostgreSQL 证明唯一竞争、修改后重复初始化、原子回滚和 Actor。第四条 E2E 只证明三角色演示接线、真实浏览器只读和持久化读取；所有权限组合、算法边界与冲突仍由既有底层测试覆盖，不复制为全流程。

pnpm verify:full 运行静态、unit/component/contract、隔离 integration、build、race 和四条 E2E；pnpm test:e2e:stability 在同一内容上构建一次、独立执行三轮，不开启 retries。CI 保留一次完整门禁，稳定性入口显式运行，报告均放忽略目录。

## 风险与证据

稳定 ID 和不覆盖策略避免初始化与用户修改互相干扰；同 Key 其他 ID 显式冲突，不静默跳过。Actor 从真实用户读取，角色已调整时不会被重置或越权。密码和配置 seed 属于显式操作，失败阶段应清楚可诊断。

CLI 与 E2E 在 owned schema 执行，始终清理本次服务/连接/schema，不修改已有开发数据。详细结果进入 [验证记录](verification.md)。Docker 留待 D6，远端 CI 无执行记录则不声称通过。
