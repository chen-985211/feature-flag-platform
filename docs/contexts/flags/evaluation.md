# Flag 评估与匹配语义

## 归属

Flags 上下文的 EvaluationPolicy 拥有全部评估语义，后端为权威实现。前端通过 Go API 评估，不维护第二套离线算法。规则和 Flag 生命周期见 [配置文档](configuration.md)。

## 输入与结果

输入为 Key、环境和 JSON 用户属性对象。环境只允许 development、staging、production；顶层数组、null 和标量不属于合法属性对象。未知 Flag 返回明确的不存在错误，非法 JSON 返回明确输入错误。

结果至少包含布尔 value、当前 revision、来源（disabled/attribute_rule/percentage_rule/default）、命中规则 ID 或 null、是否使用默认值，以及有序判断轨迹。轨迹区分命中、未命中、缺少属性/标识与首条命中后的未计算规则。

评估是只读动作，不生成配置版本和操作历史。诊断日志不默认记录完整用户属性。

## 执行顺序

1. 从当前不可变配置快照读取完整 Flag 和有序规则。
2. 停用则直接返回 false，来源为 disabled，不称为默认值。
3. 规则按 priority 从小到大依次判断。
4. 第一条命中返回该规则配置的布尔值；false 也是终止结果。
5. 全部未命中返回 Flag 的默认值。

百分比灰度是第三类规则，与 equals/in 共用优先级和首条命中语义。属性规则与灰度的先后由配置顺序明确决定，不存在隐藏的第二轮灰度覆盖。

## 属性规则

- equals：期望值为字符串、数字或布尔标量；按类型与值匹配，不隐式转换。
- in：期望值为非空、同类型的标量数组；属性值等于任一候选值即命中。
- 属性名称是精确匹配的顶层 JSON key，不解释点号路径，不自动转换大小写或裁剪字符串。
- 缺少属性、null、数组、对象或类型不符时，该属性规则不命中。
- 数字按数值相等比较，不能因浮点精度丢失使不同大整数误命中；用户标识推荐并要求在灰度中使用字符串。
- 非法期望值在保存时拒绝，不以评估期间静默跳过无效配置代替校验。

## 百分比规则

- 使用非空字符串 `user_id`，不把数字隐式转换为字符串；缺少或无效标识则不命中，并在轨迹中说明。
- 比例使用 0～10,000 的整数基点，10,000 为 100%；界面百分比最多两位小数。
- Flag 保存一个稳定 seed。普通编辑、排序、Key 改名与比例调整不重新生成 seed。
- 确定性算法采用 SHA-256：对 UTF-8 的 `seed + NUL + user_id` 哈希，取前八字节的无符号大端整数，再模 10,000 得到 bucket。
- `bucket < percentage_basis_points` 时命中，返回规则配置的布尔值；不命中继续后续规则。
- 0% 永不命中；100% 对有效 user_id 全部命中。缺少标识时仍遵循上述不命中策略。
- 同 seed、user_id 和配置重复计算结果一致。扩大比例只改变阈值，原命中集合是新集合的子集。
- seed 随完整配置复制、发布和回滚；若发布改变目标原 seed，差异预览明确展示其影响。

同一 Flag 的百分比规则共享 seed，使用相同用户桶，避免随机重抽。属性规则可作为高优先级白名单，百分比规则可配置 true，默认值配置 false；实际返回值仍完全服从有序规则，不把“20%”误解为整个 Flag 必然只对 20% 用户开启。

## 核心测试维度

使用 Go 表驱动测试覆盖停用/默认值组合、首条 true/false 命中、规则顺序、缺失/null/类型、equals/in 边界、百分比 0/100、重复评估、比例扩量及同 seed 的跨环境一致性。

分桶固定向量验证字节编码、整数方向和阈值边界；稳定性测试验证结果契约，不能复制被测算法生成所有期望值。API/快照接线用集成和契约测试，浏览器只保留代表性路径。
