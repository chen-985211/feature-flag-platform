# Spec：正式数据库与持久化演示

状态：已完成原生验收，基线 30fc42e，结果见 [验证记录](verification.md)。用户要求对照 question.md 准备正式数据；此前方案的正常 Go 服务、开发库、现有迁移/seed、保留验收数据及重启验证已获得本次执行授权。

## 目标与范围

人工验收使用 DATABASE_URL 指向的正常 PostgreSQL 数据库与 cmd/server。当前 18091 是前端预览、18090 是会删除 owned schema 的 E2E fixture；开发库表已迁移但六张业务表为空。本次切换到正常同源服务，提供可复现初始化入口与真实配置/规则/版本/历史，并保留已有业务数据。Docker/远端 CI 仍按用户决定最后验收。

按 Large 处理数据搬迁、运行生命周期和初始化编排；Flags/Identity/Audit 业务 owner、规则、API 与 schema 均不变。题面 F01～F12 沿用，重点是 F01/F04/F11 的正常运行接线及数据库持久化；这不是 F13 容器验收。

## 不变量与边界

- 迁移与 seed 复用现有实现，重复初始化不覆盖用户密码、角色、配置或历史。
- 先备份临时 schema 与目标 public；目标业务表必须为空才导入，配置/规则/快照/真实 Actor 与历史完全一致。未确认完整导入前保留旧服务，失败恢复旧进程。旧登录会话不搬迁，切换后重新登录。
- 数据库始终为事实来源；正常服务器退出不删除 schema/数据。开发库和测试库分离，demo 入口拒绝测试库与缺失/非法 seed 密码，失败发生在数据库变更之前。
- 新演示操作必须走真实 Go API，真实用户、版本与审计同事务提交；不直接 SQL 伪造发布/回滚或业务历史。
