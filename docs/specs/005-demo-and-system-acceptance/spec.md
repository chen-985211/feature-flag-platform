# D5 Spec：演示初始化与系统验收

状态：已验收。范围和执行授权来自既定 D5 计划及用户「继续」。本任务增加持久化初始化能力，按 Large 执行，复用 DDD/Clean、SDD/TDD 和金字塔规范。

## 背景与范围

让新 checkout 经迁移、显式初始化后直接演示三角色、三环境、属性/百分比评估与版本流转；完成 F01～F12 的统一证据与稳定性检查。Docker 归 D6，不要求线上部署。本阶段不新增 API、迁移或业务上下文。

## DDD 与不变量

Flags 拥有演示配置的完整聚合、初始版本和评估；Identity 拥有账号及真实 Actor；Audit 通过公开用例在同一事务追加创建历史。平台仅装配初始化入口。

1. 演示配置使用稳定 ID；首次创建完整 revision 1，随后初始化保留所有修改，包括 Key、规则、seed、版本与历史。已有同环境同 Key 的其他配置导致明确冲突，不能接管。
2. 一次演示配置初始化的所有新配置、规则、版本、审计同时提交或回滚。并发初始化最终只有一套记录，两次调用均可成功，后一次报告保留。
3. 账号初始化保留现有密码、名称和角色。配置初始化使用实际 admin 账号的 ID、名称及当前角色，授权失败不冒用身份。账号初始化与配置事务分开，失败可以修复后重跑。

## 外部行为

保留仅初始化账号的命令，增加显式完整演示命令。密码仍来自 SEED_*_PASSWORD（8～72 字节），服务启动不隐式 seed。输出创建/保留数量，不输出凭据、评估属性或连接字符串。

首次提供 development/staging/production 同 Key 的 checkout、停用和默认值示例。development checkout 按顺序展示 equals 首条 false、in 返回 true 和 25% 灰度；另外两个环境保留不同基线以供发布差异预览。初始版本与历史均为真实创建，不伪造发布或回滚；操作指南通过实际 UI 形成后续版本。

第四条代表 E2E 证明 viewer 真实登录、读取初始化配置、评估、查看版本/历史及退出，同时通过 editor 的 production 只读呈现验证角色接线。权限全集和评估边界继续由底层验证。

## 风险、边界与确认

稳定 ID 用于识别已有演示，不依赖可修改 Key。删除演示配置后重跑会重新创建；正常 UI 当前没有删除 Flag 入口。其他用户占据演示 Key 时整体拒绝新配置，既有账号不会回退。密码校验在任何账号写入前完成。

复用 PostgreSQL 唯一约束和 ON CONFLICT 的已用模式，数据库并发及原子性必须真实验证。重复浏览器运行是本次稳定性验收，不是失败重试，也不证明长期运行容量。无待用户决定事项。
