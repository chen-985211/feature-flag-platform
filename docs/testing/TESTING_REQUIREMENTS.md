# 测试要求与完成条件

## 通用最低要求

1. 受影响格式、lint、类型、架构边界和 build 检查通过。
2. 新行为有最低有效层测试；行为修复先有真实 Red 的回归测试。
3. 持久化、事务、会话和权限有真实边界覆盖，mock 通过不能代替。
4. 相关既有测试通过，未运行/跳过项目有明确原因。
5. 结果能追溯到 Spec 验收编号或 Small 任务目标；无伪造的覆盖率与通过记录。

## 按任务要求

| 任务                        | 必要证据                                                                |
| --------------------------- | ----------------------------------------------------------------------- |
| 纯文档                      | 内部链接、格式与差异检查；不运行无关应用测试                            |
| 纯视觉 Small                | 真实受影响组件渲染、静态检查与适用主题/窄屏/焦点验证                    |
| 局部行为 Small              | unit/component TDD、相关既有回归、受影响静态检查                        |
| 新功能/业务 Large           | Spec/Plan、验收矩阵、unit TDD、必要 component/integration/contract      |
| 事务/权限/并发/schema Large | 正向、负向和边界 integration/contract、失败后状态、必要 race/迁移检查   |
| 发布交付                    | 低层完整套件、少量关键 E2E、真实 build、迁移、部署 smoke 与 README 复现 |

纯视觉例外限于不改变行为；不能用它免除保存、导航结果、权限、灰度或输入校验变化的自动化测试。业务缺陷确实无法自动化时记录原因和风险，不把它当常规例外。

## 项目必须覆盖的规则

- 停用始终 false；首条命中 false 也终止；无命中返回默认值。
- equals/in 的类型、缺失、非法输入和规则顺序。
- 百分比固定向量、0/100、标识缺失、稳定性和扩量包含关系。
- 数据库环境 Key 唯一和 Flag 内 priority 唯一。
- 全部变更入口的 revision 冲突及无部分写入。
- 配置、版本与审计原子提交；审计失败时三类数据保持原状。
- 回滚恢复完整内容并产生新版本；历史未被删除。
- 排序序列合法性、唯一约束和原子更新。
- 复制冲突、发布目标/源版本、目标并发变化与权限。
- 登录/退出/过期、真实 Actor、production 全部写入口拒绝 editor/viewer。
- 前端表单保留、结果解释、排序反馈、权限与关键导航。

## 禁止弱证明

不能只检查 HTTP 200、DOM 文本存在、截图存在、mock 被调用或测试文件数量。对应断言必须证明配置结果、版本一致性、权限结果、事务后置状态或真实交互结果。

不能以大量无效 unit 数量满足金字塔，也不能用 E2E 覆盖分支来省略核心 unit。测试失败不能靠删断言、无理由 skip 或增加重试变成通过。

## 报告

每次完成说明列出：测试新增/修改、实际执行命令与结果、未执行及原因、剩余风险。纯文档报告列出文档检查即可。验收记录中保留 Red/Green 摘要、最终门禁和相关 revision/构建标识，详细原始日志不必全部入库。
