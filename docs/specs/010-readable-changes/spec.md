# Spec：可读配置与变更说明

状态：已完成并验证，基线 71ec49f，日期 2026-10-09，见 [验证记录](verification.md)。范围包括历史摘要、规则条件、回滚/发布影响和可复制原始数据。

## 范围与不变量

按 Large 管理历史快照的解析及跨页面确认信息。仅改善前端读模型与展示，Flags/Audit/Identity 的事实归属、API/schema、数据、评估、权限、expected revision 和固定源版本语义不变。保留原始审计内容与真实操作者，不改写旧 Actor。

Audit 负责将既有结构化审计投影为摘要及变更前后对比；没有足够信息的旧记录明确退回原始数据，不猜测变更。Flags 继续使用后端版本/发布差异；共用的是纯展示语言和原始数据控件，不跨上下文读取内部模型。技术字段可折叠，用户仍可访问全部原始记录。

## 验收

| ID    | 预期                                                                                               |
| ----- | -------------------------------------------------------------------------------------------------- |
| RC-01 | 历史默认给出具体摘要、版本变化；展开只列改变的业务字段/规则，技术时间/ID 不占据对比                |
| RC-02 | 创建、编辑、启停、规则增删改/排序、复制/发布/回滚均可说明；旧/未知结构有明确保底入口               |
| RC-03 | equals/in 与灰度条件使用自然语言，优先级、true/false 与实际保存语义保持清晰一致                    |
| RC-04 | 回滚和发布确认显示目标、固定来源、变更字段/规则及新版本/保留历史的后果；冲突/权限/精确提交保持原样 |
| RC-05 | 原始 JSON 默认折叠、保留数字词法精度、可复制完整原始文本；成功/失败反馈准确，可重新尝试            |
| RC-06 | 所需原生检查与四条 E2E 通过；正常验收服务展示最后构建，原有数据库保留                              |

风险：审计存储使用 PascalCase 与 ExpectedJSON 字符串，不是前端 Flag DTO；非法/未来结构不得生成虚假摘要。大整数/大指数和字符串转义不能因格式化/描述而变值。百分比摘要只描述规则，不推测所有输入的最终评估结果。
