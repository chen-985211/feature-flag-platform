# D2 核心配置与身份 Spec

状态：已实现并通过本地验收，证据见 [验证记录](verification.md)。授权来自既定范围及用户「继续」，沿用 DDD/Clean、SDD/TDD 与测试金字塔，无新增待决策的核心语义。

## 范围与归属

Identity 拥有登录、持久化会话、admin/editor/viewer 和环境写入能力；Flags 拥有配置、equals/in 规则、评估、revision 和完整快照；Audit 拥有事务内追加及历史查询。前端维护未提交表单，服务端是配置、权限和评估的事实来源。

D2 实现列表、环境/名称/Key 搜索与启停筛选、新建、详情、基本编辑、启停、属性规则增删改、评估控制台、操作历史。原题不要求删除 Flag，不增加该入口。百分比规则、版本浏览/回滚、排序、复制/发布、完整演示配置和 Docker 保持后续阶段范围。

## 可判定验收

- D2-01：显式初始化三个角色，不重置已有账号；正确密码建立 HttpOnly 会话，错误密码和未知账号返回相同错误；到期/撤销不再允许访问。
- D2-02：全部业务 API 从服务端解析 Actor；viewer 不可写，editor 不可写 production，admin 可写全部环境；读与评估向全部角色开放。
- D2-03：修改请求要求合法 Origin 和会话绑定 CSRF；角色/Actor 不能由 JSON 伪造；退出撤销服务端会话。
- D2-04：环境与 Key 唯一，环境创建后固定；名称、Key、启停、默认值、规则可持久化；列表过滤和分页确定。
- D2-05：equals 严格类型比较；in 为非空同类型标量数组；数字精确比较，优先级为正且不重复，首条命中 false 同样终止；缺少/null/数组/对象不匹配。
- D2-06：评估只读，一次读取当前完整快照；停用 false、无命中默认值、未知 Flag/无效属性有明确错误，返回 revision、来源、命中与有序轨迹。
- D2-07：每次成功变更同时产生配置、完整版本和真实 Actor 的审计；过期 revision、重复 Key/优先级、无权限、审计失败和并发竞争不留下部分写入。
- D2-08：浏览器可完成登录→创建→规则→评估→历史→退出；保存失败保留输入，冲突提供加载最新版本入口；浅/深色、窄屏、键盘和明确权限状态可用。

对应总验收见 [交付要求](../../delivery/acceptance.md)，领域语义沿用 [评估](../../contexts/flags/evaluation.md)、[配置](../../contexts/flags/configuration.md)、[权限](../../contexts/identity/access-control.md)、[审计](../../contexts/audit/history.md)。

## 输入边界与风险

完整配置快照最大 24 KiB，保证前后变化审计小于 64 KiB；HTTP JSON 最大 64 KiB，拒绝未知字段、多份 JSON 和缺失必填字段。名称 1～160 字符、Key 1～128、属性名 1～128（精确顶层 Key）、最多 100 条规则、in 最多 100 项、priority 1～2147483647、revision 为正安全整数。名称与 Key 不允许首尾空白。数值文本最多 256 字符、指数绝对值不超过 1000，超界明确拒绝，禁止浮点舍入误命中。登录用户名 1～80、密码最多 72 字节；seed 密码至少 8 字节，通过环境配置，不写入仓库。

事务、会话及权限必须在隔离的真实 PostgreSQL 与 HTTP 边界验证，不能用隐藏按钮或 fake SQL 替代。完整门禁通过并记录真实证据才标记 D2 完成；后续范围不宣称已交付。
