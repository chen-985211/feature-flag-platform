## 提交内容

- 可运行 React 与 Go 完整源代码及锁定依赖。
- 版本化 SQL、迁移入口、可重复的显式演示 seed。
- `.env.example`、本机与 Docker 启动入口、实际 CI/验证脚本。
- Go、前端和必要真实系统测试，测试数据和 support。
- 根 `README.md`：先决条件、启动、迁移、seed、演示用户、测试、数据模型、规则语义、优先级、角色、版本/发布、设计取舍、完成状态与限制。
- 本目录工程规范、已执行 Large 的 Spec/Plan 与验收记录。
- [AI 记录](../ai/README.md)：需求决定、辅助开发过程、实际执行与验证结果，无敏感凭据。
- Dockerfile、Docker Compose、迁移/启动说明与实际验证记录。

题面允许未完成项如实说明；本次目标仍是完整范围。未完成项必须明确标记，不能以“有方案/有文档”替代实现。

## 本地复现

从新 checkout 按 README 安装固定依赖，配置环境、空库迁移与 seed，再使用一条或少量明确命令启动。不能依赖开发者绝对路径、未记录的手工建表或共享线上数据。

在同一版本上验证 build、低层套件、关键 E2E 与演示功能。演示 seed 不覆盖用户实际修改；运行中业务和审计均真实持久化。

## Docker 复现与可选部署

使用同一源代码、锁定依赖和 SQL 构建镜像；Compose 提供独立数据库、明确迁移及服务健康检查。迁移失败时应用不得被标记为就绪，持久化卷与测试数据库分离。

记录实际镜像/产物标识、迁移状态、启动命令、主要 smoke 结果与限制。未运行 Docker 时如实说明，不能以配置文件存在代替容器验证。在线平台稍后如有需求再确定，不要求域名、公开演示账号或线上地址。

全部 F01～F13 有可审查证据；没有未解释的失败或跳过；所有必要检查通过；README 与 Docker 可复现；AI 记录齐全。配置回滚与数据库恢复分别验证并说明能力边界。
