# 测试策略：严格遵循金字塔

## 地位与现状

本文拥有测试层级和 TDD 规则。[开发流程](../engineering/development.md) 负责任务分级与 SDD，[测试矩阵](TESTING_MATRIX.md) 决定具体改动的最低层级。当前只有规范，没有测试代码、配置或覆盖率结果。

## 金字塔

```text
              少量 E2E
       Integration / Contract
    大量 Unit / Component / 用例测试
          静态检查作为基础门禁
```

金字塔同时约束数量、成本和反馈速度：多数分支在底层，中层证明真实边界，顶层只证明关键系统接线。Component 归基础层，Contract 归边界层；静态检查不计作行为测试。

不能为凑数量比例添加无价值测试。审查时必须能解释各层证明的风险，不能把 E2E 当默认回归或用少量浏览器流程代替领域分支与数据库验证。

## 从低到高选择

1. 纯策略、不变量、解析、状态和用例编排是否可由 unit 证明？
2. React 事件、表单与状态是否需要 component 测试？
3. 是否依赖真实 SQL、事务、HTTP/会话或适配器，需要 integration？
4. 是否改变 API、DTO、错误或端口理解，需要 contract？
5. 是否仍有低层无法证明的关键浏览器到数据库接线，才使用 E2E？

测试层级不是代码层级的机械映射。HTTP handler 的纯错误转换可以 unit，数据库约束必须真实 PostgreSQL。应用层用例用 fake 端口测编排，真实适配器和事务另由中层证明。

## TDD

生产行为新增和修改使用 Red → Green → Refactor，包括 Small 中的行为修复。Red 必须实际执行并因预期行为缺失失败；环境或语法错误不算有效 Red。Green 只满足当前行为，Refactor 在通过状态整理职责。

缺陷留下可复现原始样本的回归测试，并覆盖同类不变量和边界。已有行为重构先使用已有或新增表征测试保护，不要求故意修改生产代码制造 Red。

纯文档、注释、格式和不改变行为的可逆视觉调整不强制 TDD。视觉细节使用真实浏览器验证；测试工具、构建配置通过配置和受影响套件验证。例外不能用于跳过业务行为或权限变化。

## 测试质量

- 断言外部结果和业务后置条件，不镜像实现步骤、私有变量或 mock 调用顺序。
- 数据最小且真实，表驱动覆盖等价类、边界与关键交互维度。
- 确定时间、ID、网络和随机源；禁止用任意 sleep 等待可观察状态。
- 不用 production/staging 数据或第三方在线服务证明本地业务逻辑。
- 事务、唯一约束与并发不能通过内存 fake 代替 PostgreSQL。
- 业务与权限断言用显式期望，截图或大型快照不是默认 oracle。
- flaky 是缺陷，先定位；隔离时必须记录原因、负责人和恢复任务，重试不能算首次通过。

## E2E 准入

新增 E2E 在 Plan 或变更报告中写明：用户目标、低层为何不足、真实系统边界、可下沉分支、稳定数据/等待方式。

初始只保留登录与退出、创建/规则/评估、跨环境发布与回滚、只读用户代表路径。表单分支、灰度桶边界、所有权限组合、错误码和视觉细节下沉，不在浏览器逐项穷举。

E2E 使用真实前端、Go API 和隔离数据库。临时局部组件渲染检查可以使用浏览器工具，但不因此增加永久完整流程 E2E。

## 覆盖与证据

覆盖率是发现遗漏的信号，不是完成证明。核心评估、授权和事务的验收矩阵必须完整覆盖，不能用全局行覆盖率掩盖未验证规则；初始不设置无依据的全仓百分比门槛。

报告列出新增测试、实际运行及结果、未运行及原因、剩余风险。进一步要求见 [测试要求](TESTING_REQUIREMENTS.md)，可执行入口状态见 [执行手册](TESTING_RUNBOOK.md)。
